# 密钥与配置分层

本文只写变量名、位置、密级与轮换方法。**任何文档、对话、报告、分享链接里都不允许出现明文值。** "明文落在服务器上"可以是工程取舍，"明文写进文档"一律禁止。

## 1. 密级

| 密级 | 定义 | 处理 |
|---|---|---|
| **S0 极密** | 泄露即可无限制使用上游资源或接管系统 | `0600`、单一属主、备好轮换预案 |
| **S1 机密** | 泄露可越权访问特定系统或消耗特定预算 | `0600`、按实例最小授权 |
| **S2 内部** | 非凭据，但暴露拓扑 | 不外发，可进内部文档 |

| 变量 | 密级 |
|---|---|
| 平台应用密钥（如 `FEISHU_APP_SECRET`） | S0 |
| 模型网关 token（`ANTHROPIC_AUTH_TOKEN`） | 填 master key 是 S0，填专属虚拟 key 是 S1 |
| `PI_KEY` 等其他 CLI 凭据、git 机器人私钥 | S1 |
| 应用 ID、网关地址、放行名单 open_id | S2 |

网关 token 用有预算与限流的专属虚拟 key，不用 master key：泄露损失有上限，账单能按 key 归因。

## 2. 占位符机制

```
compose 的 env_file  →  真值，宿主文件 0600，不进 git
config.toml          →  只写 ${占位符}，进 git
entrypoint           →  启动前校验每个占位符可解析，缺则 exit 2 并列全
```

```toml
# config.toml
[projects.platforms.options]
app_id = "${FEISHU_APP_ID}"
app_secret = "${FEISHU_APP_SECRET}"
```

不能用 shell rc 文件：agent 是非交互子进程，读不到 `~/.zshenv`、`~/.bashrc`、`/etc/profile.d`，变量会静默失效。

## 3. 谁能读到这些

```toml
mode = "bypassPermissions"    # agent 执行任何命令不再询问
allow_from = "*"              # 任何平台用户都能驱动
```

两者叠加：**任何能在聊天平台找到这个机器人的人，都能让 agent `cat` 出容器内全部密钥。** `allow_from = "*"` 只适合本地测试，这是从测试迁到生产最容易漏的一步。

| 防线 | 作用 |
|---|---|
| `allow_from` / `admin_from` 改成明确的 open_id 列表 | 唯一真正挡住"谁能驱动 agent"的机制 |
| 一信任域一容器 + 每实例独立 `env_file`，逐项注入不整目录挂 | 每个 agent 只读它需要的密钥 |
| 虚拟 key 而非 master key | S0 降成 S1 |

**已知未封的口子之一：容器之间不隔离。** 所有 agentbox 容器共用一张 `agentbox` 网络（见 [MULTI_PROJECT §6](MULTI_PROJECT.md)），互相网络可达。信任域的边界是 `env_file` 与卷，不是网段：A 域的 agent 连不上 B 域的密钥，但连得上 B 域的容器。

**已知未封的口子之二：出站不受限。** 容器必须能出站连平台与模型网关，compose 没有做 egress 白名单（`internal: true` 会连平台一起切断）。这意味着一旦 agent 被提示注入，它可以把环境里的密钥发到任何外网地址。上面三道防线都是在缩小"谁能驱动 agent"与"泄了损失多大"，没有一道能阻止外传本身。生产环境要按这个前提评估：要么接受，要么在容器外用网络策略或代理只放行必要目标。egress sidecar 见 `ROADMAP.md` 已否决项。

## 4. 配置分层

| 层 | 内容 | 进 git |
|---|---|---|
| L1 镜像 | 工具链、用户、路径契约 | 是 |
| L2 实例声明 | `config.toml`，只含占位符 | 是 |
| L3 编排 | `docker-compose.yaml`、非密钥变量 | 是 |
| L4 密钥 | `examples/<name>/env`、私钥 | **永不** |

L4 只由可信通道直传或人工在宿主写入，不经第三方服务。

## 5. 红线

1. 明文密钥不进 git、文档、聊天、报告、分享链接。
2. 密钥文件 `0600`，发现 `644` 立即收紧。
3. env 模板以 `.example` 结尾，只放 `xxxx` 形态占位值；仓库不允许出现未加 `.example` 的 env 文件（`test.sh` 断言，`.gitignore` 忽略）。
4. 改完密钥文件删掉 `cp -a` 留下的 `.bak`，它们让旧凭据继续留在盘上。
5. 生产写操作必须人工明确授权。

## 6. 泄露应急

| 泄露项 | 立即动作 |
|---|---|
| 平台应用密钥 | 平台后台重置 → 更新 `env_file` → 重建容器 → 查应用调用日志 |
| 网关虚拟 key | 重签 → 换 `env_file` → 查该 key 花费明细 |
| 上游 master key | 改密钥源 → 滚动重启网关 → 通知依赖方 |
| git 机器人私钥 | 远端删公钥 → 生成新密钥 → 挂新公钥 → 查账号事件 |

"改了声明式配置"不等于"吊销了远端凭据"，应急时直接调 API 或到控制台操作。
